# BUILD A COMPLETE AI-BASED MISSING PERSON DETECTION AND ALERT SYSTEM

You are an expert full-stack developer, AI/ML engineer, UI/UX designer, and database architect.

I want you to build a complete production-style web application called:

**AI-Based Missing Person Detection, Sighting and Alert System**

The application should help authorized users register missing-person cases, store their photographs and details, allow the public to submit possible sightings, use AI-based facial matching to identify possible matches, and provide an administrator dashboard to manage cases, sightings, matches, and alerts.

IMPORTANT:

* Build the COMPLETE working project.
* Do not create a fake/demo-only interface.
* All major buttons and forms must actually work.
* Frontend, backend, database, authentication, image upload, AI matching, APIs, and dashboard must be connected.
* Do not leave TODO placeholders.
* Do not use mock data after the actual database is implemented.
* Make the project easy to run and deploy on Replit.
* If a library or technology causes deployment problems on Replit, use a reliable alternative.
* Keep the architecture clean and modular.
* Do not unnecessarily rewrite working functionality if an existing project is being imported.

### Authentication

Roles:

1. Admin
2. Investigator
3. Public User

Use JWT-based authentication.

Passwords must be securely hashed.

Never store plain-text passwords.

### AI / Face Matching

Implement facial feature extraction and similarity matching.

If Python-based face recognition is easier and more reliable, create a separate Python AI service and connect it to the Node.js backend through an API.

The AI system should:

1. Accept an uploaded photograph.
2. Detect faces.
3. Extract facial features/embeddings.
4. Compare the face with registered missing-person faces.
5. Calculate similarity/confidence.
6. Return the best matches.
7. Return multiple candidates where appropriate.

Do not claim that an AI match is certain identification.

Use wording such as:

* High-confidence possible match
* Possible match
* No reliable match
